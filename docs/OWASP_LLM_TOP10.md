# OWASP Top 10 for LLM Applications (2025): mapping to code and tests

Source list: [genai.owasp.org/llm-top-10](https://genai.owasp.org/llm-top-10/) (2025 edition; still the current
edition when checked on 2026-11-09). Companion to [THREAT_MODEL.md](THREAT_MODEL.md) (STRIDE) and
[SECURITY_LIMITATIONS.md](SECURITY_LIMITATIONS.md). "Tested" means a named test or a saved report in this repo;
everything here is a local demo over fictional data, not a certified control.

| Risk | How it shows up here | Controls in code | Tests / saved evidence | Residual risk (not mitigated) |
|---|---|---|---|---|
| **LLM01 Prompt injection** | Documents contain text addressed to "AI tools" (six injection fixtures); questions say "ignore your access rules". | Authorization never reads content or prompts (`authz.decide`, `access.authorized_versions`). Passages are wrapped as untrusted data and the system prompts say so (`generate.SYSTEM`, `claude_citations.SYSTEM`). The generator has no tools. Output may cite only passages in the authorized pack (`generate.validate_output`; `claude_citations.map_citation` for Claude). Extractive answers never quote a flagged sentence. Passages and questions are flagged (`evidence.detect_injection`). | `tests/test_generation.py` (scripted model that obeys injections), `tests/test_claude_citations.py::test_hostile_or_broken_outputs_are_rejected`, adversarial `injection` + `generation` sections (`eval/reports/adversarial.json`), and the same sections answered by a real local model (`eval/reports/adversarial_generative.json`). | The regex flag is a heuristic and will miss new phrasings. A model can still *mention* injected text in prose; such sentences are labelled by the support check, not blocked. |
| **LLM02 Sensitive information disclosure** | Cross-tenant and in-tenant (clearance, groups, ethical walls) confidential documents. | Authorized view computed before BM25, embeddings, snippets, prompts or logs; per-tenant FTS5 tables; uniform 404 / `not_found` for forbidden and missing; prompts built only from the authorized pack; audit detail redacted and never stores passages. | `test_zero_leaks_through_search_and_ask`, `test_direct_api_reads_are_denied`, `test_prompt_contains_only_authorized_passages`, `test_forbidden_documents_never_reach_the_request` (Claude request), `tests/test_mcp_server.py::test_forbidden_equals_missing_and_zero_forbidden_content`, `test_audit_log_redacts_secrets_and_never_stores_document_text`; isolation sweep with real-model prompts checked for canaries (`adversarial_generative.json`). | The Claude provider sends the *authorized* passages to a third-party API (opt-in, needs a key). In-tenant BM25 statistics include unreadable documents (rank-order inference). |
| **LLM05 Improper output handling** | Model output could carry invented ids, numbers, markup or instructions. | Model output is parsed (JSON or citation blocks), never executed or used to build queries; spoofed ids or out-of-range citation indices reject the whole output; every citation is re-verified against stored text and the asker's ACL (`service.run_query` → `verify_citation`); numbers not in the cited spans mark a sentence unsupported; the UI renders text only (React escaping); uploaded HTML is stored and served as inert text. | `test_invented_passage_id_rejects_whole_output`, `test_invented_numbers_flagged_unsupported`, `test_garbage_output_falls_back_to_extractive`, Claude `tampered_cited_text` / `bad_document_index` / `bad_block_range` fixtures, `test_html_is_stored_and_served_as_inert_text`. | The support check is lexical + numeric; it cannot prove a fluent paraphrase is faithful (measured: see the faithfulness section of [RAG_EVALUATION.md](RAG_EVALUATION.md)). |
| **LLM06 Excessive agency** | An assistant with tools could read or release documents on its own. | The generator has no tools. The MCP server exposes three read-only tools, annotated read-only, with the identity bound at launch and no identity parameters. The one external action (brief release) needs a different human approver. | `tests/test_mcp_server.py::test_tools_take_no_identity_arguments`, `test_identity_arguments_cannot_escalate`, `test_external_release_requires_second_person_approval`, `test_upload_requires_admin_and_forces_tenant`. | MCP client authentication is "whoever can start the process" (stdio), like the mock login. |
| **LLM08 Vector and embedding weaknesses** | Shared vector/lexical indexes could return another tenant's or a forbidden chunk; embeddings could be inverted. | Dense scoring runs only over embeddings of authorized chunks; FTS5 `MATCH` is restricted to authorized chunk ids inside SQL; one FTS index per tenant; no endpoint returns embeddings; retrieval log (audit) records refs only. | `test_retrieval_candidates_are_authorized_chunks_only`, `test_no_endpoint_returns_embeddings`, `test_zero_leaks_through_search_and_ask` (1,796 probes), MCP search sweep. | Embeddings are stored unencrypted in SQLite; within-tenant BM25 document frequencies include unreadable documents. |
| **LLM10 Unbounded consumption** | Large queries/uploads, request floods, long generations, paid API spend. | 500-char queries, 4 MB body cap, 2 MB upload cap, per-identity rate limit (429), source pack capped at 6 passages, `max_tokens` caps (local 4,096; Claude 16,000), Claude never auto-selected; per-answer token usage and a list-price cost estimate are shown. | `test_rate_limit`, `test_oversized_body_rejected`, `test_query_length_limit`, `test_unsafe_uploads_rejected`, `test_never_selected_automatically`. | No per-user token or dollar budget for the Claude provider; the limiter is in-process only. |
| LLM03 Supply chain | Python/npm dependencies, embedding model download, local LLM weights. | Exact pins + `uv.lock` / `package-lock.json`; `make audit-deps` (pip-audit, npm audit); license gate fails on GPL/AGPL runtime deps; embedding model id pinned in config. | `eval/reports/licenses.json`, `make licenses`. | No SBOM signing, no model-weight hash pinning, CI disabled by owner policy (run `make ci` locally). |
| LLM04 Data and model poisoning | Uploaded or planted documents. | Uploads parsed, size/type-checked and quarantined on failure; versions immutable and checksummed; no training or fine-tuning on user data. | `test_unsafe_uploads_rejected`, `test_malicious_filename_and_corrupt_upload_quarantined`, `test_new_version_supersedes_and_old_citations_stay_valid`. | No content-provenance verification of the corpus itself. |
| LLM07 System prompt leakage | Prompts could hold secrets or be the only access control. | System prompts contain no secrets or permissions and are committed in the repo; access control never depends on the prompt. | Code review (`generate.SYSTEM`, `claude_citations.SYSTEM`, `eval/faithfulness/judge_prompt_*.txt`). | None specific; a leaked prompt reveals nothing that is not already public. |
| LLM09 Misinformation | Fluent but wrong or unsupported answers. | Exact citations, abstention when coverage is low, per-sentence support labels, side-by-side conflicts, default extractive mode, and a measured faithfulness eval with an LLM judge calibrated against reference labels. | `eval/reports/latest.json` (answer support, abstention F1), `eval/reports/faithfulness.json`. | Reference labels are AI-drafted pending owner review; the judge shares a model with the generator. |
